Продолжить обучение с того места, где остановились

Два помощника OpenCode: преподаватель улучшает доступное объяснение, студент возвращается к трудному месту. Цель, журнал и следующий шаг сохраняются в файлах между диалогами.

Что получится

Проект преподавателя

План доступного занятия, наблюдение о непонятной формулировке, исправленный план и отчёт. Агент предлагает педагогические опоры; окончательное решение принимает преподаватель.

Проект преподавателя ZIP

Проект студента

Объяснение готового текста, сохранённая трудность, план повторения и один ближайший вопрос. Ответ студента остаётся его работой.

Проект студента ZIP
Все данные примера синтетические. Даты, события T01/S01 и изменения T02/S02 — условная модель процедуры. Это не история реальных студентов или прошедших недель. Агент не ставит диагнозы, не распознаёт аудио и не отправляет уведомления по расписанию.

Сначала срок условной процедуры — 10 ноября. Затем он меняется на 12 ноября вместе с целью. Подготовленные файлы сохраняются, а применение плана и ответ на вопрос остаются будущими действиями.

Программы и доступ

Если OpenCode уже настроен после 3.4, повторная установка не нужна. Нужны компьютер Windows или macOS, терминал, редактор текста или VS Code, интернет и доступная модель с авторизацией своего провайдера. Отдельный MCP-сервер и планировщик не требуются.

Ниже маршрут OpenCode 1, совместимый с командами этой практики. На машине подготовки установлен 1.18.29. OpenCode 2 использует ту же команду, но другой пакет; выбирайте версию осознанно. Факт установки у автора не означает проверку вашей модели или системы.

Windows с нуля

  1. Установите Node.js LTS для своей архитектуры с официальной страницы; в мастере оставьте добавление в PATH. Закройте и снова откройте PowerShell.
  2. Проверьте node --version и npm --version. Затем выполните команду установки ниже. Если PowerShell блокирует npm.ps1, используйте npm.cmd install -g opencode-ai или командную строку; не меняйте глобально политику безопасности ради урока.
  3. Полностью извлеките ZIP через «Извлечь всё». Откройте папку проекта с AGENTS.md в корне. В адресной строке Проводника введите powershell и нажмите Enter.
  4. Выполните Get-Location, Get-ChildItem: должны быть видны state.md, AGENTS.md и рабочие папки. Запустите opencode --version, затем opencode.

При проблемах совместимости официальный рекомендованный маршрут — Windows с WSL. Подробные экраны и альтернативный Desktop — в теме 3.4.

macOS с нуля

  1. Установите Node.js LTS через официальный установщик для Apple Silicon или Intel с сайта Node.js; откройте новый Терминал.
  2. Проверьте node --version, npm --version. Установите OpenCode 1 командой ниже. При ошибке прав используйте официальный вариант установки из документации; не запускайте произвольно все команды через sudo.
  3. Дважды щёлкните ZIP в Finder, затем найдите папку проекта с AGENTS.md. В Терминале введите cd , перетащите эту папку и нажмите Enter.
  4. Проверьте pwd и ls. Запустите opencode --version, затем opencode.

Если Node.js не нужен для других задач, в официальной документации OpenCode 1 есть альтернативные установщики. Для Desktop используйте инструкцию 3.4.

node --version
npm --version
npm install -g opencode-ai
opencode --version
opencode

Команда относится к OpenCode 1 и приведена в официальной инструкции. На текущей странице OpenCode 2 указан другой пакет; не выполняйте оба маршрута поверх друг друга.

Подключите модель и проверьте запись

  1. Внутри OpenCode 1 введите /connect, выберите доступного провайдера и пройдите его авторизацию. Затем /models и выберите модель. Доступ и оплата зависят от провайдера; ключи в файлы проекта не копируйте.
  2. Отправьте: «Назови текущую рабочую папку и перечисли файлы в её корне. Ничего не меняй». Проверьте, что открыта нужная роль.
  3. Для создания файлов используйте режим с записью, например Build в OpenCode 1. Если выбран Plan, переключите режим; просматривайте изменения и запросы доступа к своей учебной папке.
  4. Отправьте: «Создай outputs/setup_check.md с одной строкой: учебная папка открыта. Другие файлы не меняй». Откройте файл. Это проверка записи, а не прогресс обучения.

После изменения AGENTS.md начните новый диалог. В OpenCode 1: /exit, повторный opencode из той же папки, затем /new. Старую сессию не выбирайте. Сверяйте доступные команды через /help своей версии.

state.md — ваша текущая рабочая точка. examples/ — подписанные синтетические образцы до/после; не копируйте их в свой журнал как реальные события. history/ хранит точные старые состояния, outputs/ — версии подготовленных материалов. Названия ovz сохранены из исходного упражнения и не означают диагностику.

Учебный отрывок по охране труда используется для понимания текста. Он сокращён и не заменяет полный порядок допуска и выполнения работ. Перед применением в реальном обучении преподаватель проверяет предметное содержание по действующим утверждённым материалам.

Порядок повторения

  1. Преподаватель: T0 → T1. Прочитайте исходное состояние; создайте доступный план. Проверьте связь «барьер → опора → вопрос», сумму этапов 45 минут и статус «план подготовлен». Пример: plan_v1.md.
  2. Преподаватель: T2. Внесите условное наблюдение T01; сравните версии плана. Изменяется опора для двух понятий. Пример: plan_v2.md, запись наблюдения.
  3. Студент: S0 → S1. В отдельной папке создайте/пересоздайте AGENTS.md через требования; сверьте границы и сохранение состояния. В ZIP уже есть рабочий образец для сравнения. После правки начните новый диалог.
  4. Студент: S2 → S3. Разберите готовый текст, затем сохраните синтетическое сообщение о трудности. Ответ самопроверки за студента не заполняется. Примеры: разбор, трудность, повторение.
  5. Новые диалоги: N1. По очереди в каждой папке завершите диалог и начните новый. Запросите продолжение только по рабочим файлам. Ожидается прежний срок 10 ноября, собственный следующий шаг для каждой роли и отсутствие выдуманного освоения. Примеры состояний: преподаватель, студент.
  6. Новые условия: T3 и S4. Измените цель и срок на 12 ноября. Сохраните старые файлы, записи и точную прошлую копию состояния. Получите новые версии и отчёты. Синтетические примеры: plan_v3.md и review_v2.md.
  7. Ещё один новый диалог: N1. Убедитесь, что новый срок восстановлен без старого чата. Сравните состояние до/после, журнал и отчёт. В собственной дисциплине заменяйте материал и контекст; синтетические события не переносите в реальную историю.
