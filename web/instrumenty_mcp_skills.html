Подключаем данные и действия

MCP своими руками

Model Context Protocol — стандарт общения между ИИ-приложением и внешним сервером. Сервер публикует строго определённые данные, действия и шаблоны, а клиент решает, когда предложить их модели.

MCP похож на учебную лабораторию с контролируемым входом

Модель не получает «доступ ко всему компьютеру». Вы создаёте маленький сервер и явно определяете, какие папки он видит, какие функции разрешены и где требуется подтверждение преподавателя.

Host + ClientClaude, Codex, IDEПоказывает инструменты модели и получает согласие пользователя
→
MCP ServerВаш адаптерПроверяет входные данные и разрешения, выполняет функцию
→
External SystemФайлы, LMS, GitHubРеальные материалы, проекты, расписание или база данных
resources

Данные для чтения: методичка, программа дисциплины, карточка проекта. Аналог безопасного GET-запроса.

tools

Функции, которые можно вызвать: найти файл, проверить репозиторий, создать черновик объявления.

prompts

Повторяемые шаблоны взаимодействия: «план занятия», «разбор проекта», «вопросы к защите».

Структура учебного MCP-сервера
college-materials-mcp/ ├── server.py # tools, resources, prompts ├── pyproject.toml # зависимость mcp[cli] ├── materials/ # только разрешённые файлы │ ├── программа.md │ └── занятие-01.md └── tests/ └── test_server.py
Граница безопасности: сервер работает только с папкой materials/, а не со всем диском.
Порядок создания
  1. Опишите одну задачуНапример: найти и прочитать утверждённую методичку.
  2. Сузьте область доступаОдна папка, один репозиторий или тестовая база.
  3. Определите контрактИмена, параметры, типы результата и понятные docstring.
  4. Добавьте проверкиЗапрет выхода из папки, лимиты размера, подтверждение записи.
  5. Проверьте в InspectorПосмотрите, что сервер действительно публикует клиенту.

Рабочий пример на Python: FastMCP, установка и запуск

Пример использует стабильный Python SDK MCP. Он читает только Markdown-файлы из папки materials и не выполняет запись.

server.py
from pathlib import Path

from mcp.server.fastmcp import FastMCP

mcp = FastMCP("college-materials")
MATERIALS = (Path(__file__).parent / "materials").resolve()


def safe_file(name: str) -> Path:
    """Разрешить только .md-файлы внутри materials/."""
    candidate = (MATERIALS / name).resolve()
    if MATERIALS not in candidate.parents:
        raise ValueError("Файл находится вне разрешённой папки")
    if candidate.suffix.lower() != ".md":
        raise ValueError("Разрешены только Markdown-файлы")
    if not candidate.is_file():
        raise FileNotFoundError(name)
    return candidate


@mcp.resource("material://{name}")
def read_material(name: str) -> str:
    """Прочитать один утверждённый учебный материал."""
    return safe_file(name).read_text(encoding="utf-8")


@mcp.tool()
def list_materials() -> list[str]:
    """Показать доступные методические материалы."""
    return sorted(path.name for path in MATERIALS.glob("*.md"))


@mcp.prompt(title="План занятия")
def lesson_plan(topic: str, minutes: int = 90) -> str:
    """Создать инструкцию для проектирования занятия."""
    return (
        f"Составь план занятия по теме «{topic}» на {minutes} минут. "
        "Используй только материалы MCP. Добавь цели, практику, "
        "контроль понимания и критерии результата."
    )


if __name__ == "__main__":
    mcp.run(transport="stdio")

Skill своими руками

Skill — это папка с инструкцией для агента. Она объясняет, когда включаться, какую последовательность соблюдать, какие материалы использовать и в каком формате отдавать результат.

Промпт

Разовая просьба в чате. Хорош для уникальной задачи, но методика легко теряется.

Канал к данным и действиям. Он знает, как получить файл, но не обязан знать педагогическую методику.

Что писать в SKILL.md
  1. Точный триггерКакие слова и задачи должны активировать skill.
  2. Входные данныеТема, аудитория, длительность, источники, ограничения.
  3. Рабочие шагиПоследовательность действий, проверки и точки согласования.
  4. Формат результатаСтруктура плана, таблицы, отчёта или обратной связи.
  5. ЗапретыНе выдумывать источники, не оценивать личность, не публиковать без подтверждения.

# Проектирование занятия

1. Уточни тему, аудиторию, длительность и ожидаемый результат.
2. Изучи предоставленные материалы. Не выдумывай источники.
3. Сформулируй 2–4 измеримые учебные цели.
4. Построй маршрут: вход → объяснение → практика → проверка → рефлексия.
5. Добавь задания базового и повышенного уровня.
6. Верни результат в формате:
   - цели;
   - тайминг;
   - действия преподавателя;
   - действия студентов;
   - материалы;
   - проверка результата.

Окончательное решение о содержании и оценивании принимает преподаватель.
Главная строка — description. Она должна одновременно объяснять, что делает skill и когда его следует использовать.

# Lesson Designer

## Вход

Собери или уточни:
- тему и специальность;
- возраст и стартовый уровень группы;
- длительность;
- доступное оборудование;
- обязательные источники;
- форму итогового результата.

Если обязательных данных нет, задай не более трёх коротких вопросов.

## Процесс

1. Через разрешённый MCP получи только относящиеся к теме материалы.
2. Отдели требования программы от дополнительных идей.
3. Сформулируй измеримые цели: действие + объект + критерий.
4. Подбери одну центральную практическую задачу.
5. Построй тайминг с резервом не менее 10%.
6. Добавь формирующую проверку до итогового задания.
7. Создай базовый и усложнённый вариант.
8. Проверь соответствие целей, деятельности и оценивания.

## Формат результата

### Паспорт
Тема, аудитория, длительность, оборудование.

### Цели
Таблица: цель | наблюдаемый результат | способ проверки.

### Сценарий
Таблица: время | преподаватель | студенты | материалы.

### Практика
Условие, ожидаемый артефакт, критерии готовности.

### Риски
Типичные затруднения и способы поддержки.

## Ограничения

- Не придумывай нормативные требования и источники.
- Не включай персональные данные студентов.
- Не выставляй итоговые оценки автоматически.
- Явно отмечай предположения и материалы, которых не хватило.
Как проверить, что Skill действительно полезен
Trigger

Skill включается на нужных запросах и не вмешивается в нерелевантные задачи.

Repeatability

Для похожих входных данных структура и критерии результата остаются стабильными.

Guardrails

Ограничения реально влияют на поведение: источники не выдумываются, решения не публикуются автоматически.

Интеграции для агента

Каталог полезных MCP

Уровень доступа — часть педагогического дизайна. Чтение подходит для первых экспериментов, запись требует подтверждения, а браузерные и кодовые действия лучше выполнять в песочнице.

Правило старта:сначала подключите один MCP в режиме только чтения и проверьте журнал вызовов на нескольких учебных запросах.

Filesystem MCP

Только чтение

Доступ к выделенной папке с методичками, шаблонами и обезличенными работами.

Найди материалы по теме «эмбеддинги» и составь карту занятия.

Google Drive MCP

Только чтение

Поиск документов и сбор информации из общей папки команды.

Собери сводку решений из протоколов последних трёх встреч.

GitHub MCP

Только чтение

Репозитории, Issues, Pull Requests, история и содержимое студенческих проектов.

Объясни архитектуру проекта и подготовь вопросы к защите.

Git MCP

Только чтение

Локальная история изменений без обязательной публикации проекта в облако.

Сравни две версии и объясни, какие ошибки исправила команда.

Fetch / Search MCP

Только чтение

Получение веб-страниц и поиск актуальных первичных источников.

Найди официальную документацию библиотеки и проверь пример кода.

Playwright MCP

Песочница

Открытие сайта, заполнение форм, проверка интерфейса и создание скриншотов.

Пройди сценарий регистрации в тестовой версии сайта и опиши ошибки.

PostgreSQL / SQLite MCP

Только чтение

Безопасные запросы к учебной базе и объяснение структуры данных.

Покажи динамику выполнения заданий без имён студентов.

Memory MCP

С подтверждением

Хранение решений, терминов и состояния длительного проекта кружка.

Запомни утверждённые роли команды и следующий контрольный срок.

Calendar MCP

С подтверждением

Чтение расписания и создание консультаций, защит и дедлайнов.

Найди свободное окно и подготовь событие, но не создавай без подтверждения.

Telegram / Slack MCP

С подтверждением

Сводки обсуждений и подготовка объявлений для группы или кружка.

Сделай черновик дайджеста недели и покажи перед отправкой.

n8n MCP

С подтверждением

Запуск заранее собранных автоматизаций из ИИ-клиента.

Запусти сценарий напоминаний только после показа списка получателей.

Moodle / Stepik MCP

С подтверждением

Собственная интеграция для заданий, курсов и обезличенной аналитики.

Подготовь черновик обратной связи по типичным ошибкам группы.

Повторяемые педагогические методики

Каталог образовательных Skills

Название skill должно отражать действие, описание — момент применения, а результат — быть проверяемым преподавателем. Ни один skill не принимает дисциплинарные или итоговые оценочные решения самостоятельно.

План занятия с целями, таймингом, практикой и проверкой понимания.

assessment-builder

Тесты, открытые вопросы и практические задания разных уровней.

«Подготовь входную и итоговую диагностику по Python».
rubric-builder

Измеримые критерии, уровни выполнения и понятная шкала.

assignment-differentiator

Базовый, стандартный и усложнённый варианты одного задания.

fact-checking-teacher

Стартовый комплект на первую неделю
  1. Выберите один процессНапример, подготовку плана занятия, а не «автоматизацию всей работы».
  2. Создайте один skilllesson-designer с понятным форматом результата.
  3. Подключите один источникFilesystem или Drive MCP только к отдельной папке.
  4. Проведите пять тестовых запросовОбычный, неполный, ошибочный, рискованный и нерелевантный.
  5. Исправьте методикуУточните триггер, шаги и ограничения по результатам тестов.
7
Человек сохраняет контроль

Безопасный запуск

MCP расширяет возможности модели, поэтому цена ошибки растёт. Удобство не должно отменять минимальные права, проверку источников и ответственность преподавателя.

✓

Сначала безопасный черновик

Хорошая образовательная автоматизация предлагает, объясняет и готовит материалы. Отправка, публикация, удаление и итоговое оценивание остаются под подтверждением человека.

  • Начинайте с режима только чтениеЗапись добавляйте только после успешного тестирования конкретного сценария.
  • Ограничивайте областьОтдельная папка, учебный репозиторий, тестовая база или специальный аккаунт.
  • Не передавайте персональные данныеОбезличивайте работы и не помещайте оценки, контакты и медицинские сведения в открытые сервисы.
  • Не храните ключи в коде и SkillИспользуйте переменные окружения и штатные механизмы авторизации.
  • Требуйте подтверждение действияПеред отправкой сообщения, публикацией, изменением записи или удалением.
  • Проверяйте источники и результатыИИ может неверно интерпретировать документ, код, критерий или статистику.
  • Тестируйте сторонние MCP и Skills в песочницеИзучите код, опубликованные возможности, сетевые обращения и реальные права.
  • Оставляйте оценочные решения преподавателюSkill может подготовить рубрику и обратную связь, но не решать судьбу студента.
