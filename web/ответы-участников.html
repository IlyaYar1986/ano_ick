Критика кода и сократический диалог
Как спровоцировать ИИ на критику? Как заставить задавать наводящие вопросы, чтобы вы сами пришли к решению? На примере рефакторинга кода.
ИнструментМодельЖелезо
LM StudioQwen3-Coder-30B (MoE)24 ГБ VRAM / 32 ГБ ОЗУ
LM Studio / OllamaQwen2.5-Coder-14B12 ГБ VRAM / 16–32 ГБ ОЗУ
Ollama + Open WebUIQwen2.5-Coder-7Bофисный ПК 16 ГБ ОЗУ
💻Честная оценка — Qwen2.5-Coder-7B на CPU
  • Сократический диалог по конкретной функции — работает хорошо: формат вопрос-ответ не требует анализа всего кода сразу.
  • Ревью простого кода (до 50 строк) — находит отсутствие валидации, дублирование, неочевидные имена.
  • Архитектурный ревью (SOLID, паттерны, межмодульные связи) — поверхностный, половину проблем пропускает.
  • Для обучения и рефакторинга небольших функций — достаточно. Для code review перед релизом — GigaChat или 14B+.
Онлайн-аналоги
  • GigaChat — есть режим для кода, данные в РФ.
  • YandexGPT / Yandex Code Assistant — встроен в IDE, данные в РФ.
  • Claude — лучший для код-ревью и сократического диалога; только для открытого кода.
Режим А — Сократический диалог
1
Запустить LM Studio или Open WebUI, выбрать модель.
2
Вставить в поле System Prompt:
System Prompt
Ты — опытный наставник по разработке ПО. Твоя единственная задача — помочь мне самому найти проблему в коде.
Правила:
1. Никогда не давай готового исправленного кода, пока я явно не попрошу.
2. На каждый мой вопрос отвечай только вопросом — задавай наводящие вопросы по методу Сократа.
3. Начни с самого широкого вопроса («Что, по-твоему, делает эта функция?»), затем сужай фокус.
4. Если я иду в правильном направлении — скажи «Верно, продолжай» и задай следующий вопрос.
5. Если я застрял после трёх попыток — дай подсказку, но не решение.
3
В чате: «Вот мой код. Помоги разобрать по Сократу: [вставить код]»
4
Отвечать на вопросы ИИ до решения, затем: «Теперь покажи правильный вариант».
Режим Б — Жёсткая критика кода
System Prompt
Ты — ведущий архитектор ПО с 20-летним опытом код-ревью. Ты известен тем, что не щадишь плохой код.
Задача: найди ВСЕ проблемы в предоставленном коде.
Проверь: нарушения SOLID, потенциальные баги и граничные случаи, проблемы производительности,
нечитаемые имена, отсутствие обработки ошибок, дублирование кода (DRY).
Формат: пронумерованный список. Каждое замечание: [строка/место] → [проблема] → [почему это плохо].
В конце задай 2 вопроса автору: почему был выбран именно такой подход.
Промпт в чат
Проведи жёсткий код-ревью. Не щади:

[вставить код]

💻Честная оценка — Qwen3-8B на CPU

Сценарий Б — Игровые задания (геймификация)
System Prompt
Ты — разработчик образовательных игр и геймификации. Создаёшь обучающие квесты
для промышленных предприятий. Твои квесты: реалистичны, основаны на реальных

Промпт — квест

Структура:

- Финальный уровень: командное испытание для 3–5 человек

Аудитория: [должность], [уровень опыта].
Промпт — тест-вопросы

Работа с текстовыми документами
Образовательные программы, отчёты, пояснительные записки, регламенты, инструкции, положения.
ЗадачаИнструментМодельЖелезо
Вопросы по документам (RAG)AnythingLLM + OllamaQwen3-8Bофисный ПК 16 ГБ ОЗУ
Переработка и редактураLM StudioQwen3-14B12 ГБ VRAM / 16–32 ГБ ОЗУ
Большие документы (50+ стр.)Open WebUIQwen3-32B24 ГБ VRAM
💻Честная оценка — Qwen3-8B на CPU
  • Прямые фактические вопросы («Что написано в пункте 4.3?», «Перечисли ответственных») — надёжно. Сильная сторона RAG.
  • Синтез из нескольких разделов — 8B иногда пропускает фрагменты или добавляет от себя. Перепроверять.
  • Документы 50+ страниц — RAG режет текст на чанки; 8B хуже восстанавливает связь между удалёнными разделами, чем 14B+.
  • Редактура текста — на 8B заметно хуже 14B: смысл сохраняет, но точность и стиль формулировок страдают.
  • Для поиска конкретных фактов в документе 8B рабочий. Для аналитики и редактуры — GigaChat или YandexGPT.
Онлайн-аналоги
  • YandexGPT «Нейроэксперт» — RAG по своим документам; данные в РФ.
  • GigaChat — работа с приложенными файлами; данные в РФ.

💻Честная оценка — Qwen2.5-Coder-7B на CPU
  • Linux (CentOS, Ubuntu) и Windows Server — стандартные задачи (systemd, cron, PowerShell, права) знает хорошо с понятными пояснениями.
  • Диагностика по тексту ошибок — хорошо интерпретирует типовые логи и предлагает разумные версии причин.

Сценарий — Получение команд с объяснением
System Prompt
Ты — системный администратор с опытом в промышленных сетях.
Знаешь Linux (RHEL/CentOS/Ubuntu), Windows Server, Cisco IOS.
Правила:
1. Давай команды пошагово — одна команда = один шаг.
2. После каждой команды: что делает и почему именно так.
3. Предупреждай о рисках.
4. Необратимые команды отмечай ⚠️.
5. В конце — команда для проверки результата.
Промпт-шаблон
Оборудование: [сервер на CentOS 7]
Задача: [настроить автозапуск nginx при перезагрузке]
Текущее состояние: [nginx установлен, но не стартует автоматически]
Ограничения: [нет интернета, нельзя ставить новые пакеты]
Примеры задач
# Cron-задание на бэкап
Настрой cron: каждую ночь в 02:00 бэкап /var/data → /backup/data_YYYYMMDD.
Старые бэкапы старше 30 дней удалять автоматически.

# Пользователь Windows Server
На Windows Server 2019 через PowerShell: создать пользователя «operator1»,
добавить в группу «Операторы», пароль истекает через 90 дней.

# Диагностика по логу
Диагностируй: сервис не запускается, вот лог: [текст лога]
Какие 3 наиболее вероятные причины? Дай команды для диагностики каждой.

💻Честная оценка — Qwen2.5-Coder-7B на CPU
  • Python/Bash скрипты простой сложности (Netmiko, парсинг вывода) — справляется, нужны итерации и проверка.
  • Конфигурация сетевого оборудования — 7B генерирует правдоподобные конфиги с синтаксическими и логическими ошибками. Для продуктивных сетей неприемлемо.
  • RADIUS/LDAP/802.1X — сложные сценарии авторизации требуют точных протокольных деталей; 7B ненадёжна.
  • На офисном ПК для конфигов оборудования используйте GigaChat на корпоративном тарифе с обезличенными примерами — это надёжнее, чем 7B. Локальная 7B подходит только для простых скриптов.
Онлайн-аналоги
  • GigaChat / YandexGPT — конфиги и скрипты; данные в РФ.
  • Claude / ChatGPT — лучшая глубина по сетевым протоколам; маскируйте реальные IP, пароли, домены.
🔴Топология сети, схема авторизации и учётные данные — чувствительная информация. Для реальных конфигов предприятия: только локальные модели или GigaChat on-premise.

System Prompt

💻Честная оценка — Qwen3-8B на CPU
  • Извлечение структуры из текста стандарта (процессы, участники, результаты) — хорошо. Задача «найти и оформить», а не «придумать».
  • Список вопросов для интервью с владельцем процесса — разумный стартовый набор.
  • Gap-анализ — находит очевидные несоответствия; тонкие противоречия и нюансы формулировок пропускает.
  • Генерация drawio XML — для простых схем (5–8 блоков) работает. Для сложных процессов с ветвлениями возможны ошибки разметки; открывайте в drawio и правьте.
  • 8B достаточно для подготовки к интервью и структуризации стандарта. Для серьёзного gap-анализа и сложных диаграмм — GigaChat или 14B+.

  • drawio Desktop, bpmn.io Desktop — бесплатные офлайн-редакторы диаграмм.

Сценарий В — IDEF0 через drawio
Промпт — структура IDEF0
Опиши IDEF0-диаграмму (нотация SADT) для процесса «[название]».
Для каждого функционального блока:
- Название блока
- Входы (стрелки слева): что поступает на обработку
- Выходы (стрелки справа): что получается в результате
- Управление (стрелки сверху): нормативные документы, условия
- Механизмы (стрелки снизу): кто и с помощью чего выполняет

Уровень A0: один главный блок.
Уровень A1: 3–5 дочерних блоков с потоками между ними.
Выведи текстовым описанием — я внесу в drawio вручную.
Сценарий Г — Gap-анализ «как есть» vs стандарт
Промпт
У меня есть:
1. Описание процесса «как есть» по результатам интервью: [текст]
2. Требования стандарта/регламента: [текст или «загружен в базу знаний»]

Проведи gap-анализ:
- Что соответствует требованиям?
- Что противоречит? (с указанием пункта стандарта)
- Что есть в реальности, но не описано в стандарте?
- Что требует стандарт, но отсутствует в реальном процессе?
