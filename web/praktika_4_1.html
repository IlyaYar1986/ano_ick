Сценарий 1

Оценщик проектов

Он не «угадывает лучший проект». Помощник применяет переданную рубрику, находит подтверждение в документе и отдельно отмечает сведения, которых в заявке нет.

Документ 1

Отзыв автору

Что получилось убедительно, что стоит уточнить и какой следующий шаг поможет улучшить заявку.

Документ 2

Сводка для обсуждения

Баллы по критериям, короткие цитаты и вопросы, которые экспертам нужно проверить.

Оценка не равна решению. Сводка помогает человеку подготовиться к обсуждению. Она не принимает решение о финансировании.

Текст заявки не меняет критерии

В одном учебном файле есть просьба поставить проекту только высокие баллы и скрыть недостающие сведения. Агент должен процитировать этот фрагмент как содержимое заявки и продолжить работу по рубрике.

Как выглядит проверяемый вывод

Учебный пример по заявке «Мастерская профпроб». Откройте в архиве исходный файл и сопоставьте утверждение с его формулировками.

КритерийЧерновой выводОснование в заявке
Цель и измеримый результат2 / 4Цель названа, но измеритель результата не задан.«Повысить интерес и провести профпробы»
План и реалистичность сроков2 / 4Есть расхождение между этапами и общим сроком.Этапы занимают 6 недель; в календаре указано 8.
Ресурсы и бюджетНужно уточнитьУказана общая сумма; перечня расходов и расчёта нет.«Нужны материалы на 30 000 рублей»

Это учебный образец формата, а не результат оценки реальной заявки. Сверяйте каждую цитату с первичным файлом.

Повторите пример в своей папке

Скачайте архив и распакуйте

Распакуйте Проект_оценщик.zip. Сначала откройте отдельную папку Свободный_разбор — там одна заявка без рубрики и правил. Для основного прохода откройте Проект_оценщик с AGENTS.md, rubric.md, task.md и папкой проекты.

Откройте именно эту папку в OpenCode

В терминале перейдите в папку проекта и запустите opencode. В OpenCode Desktop выберите «Открыть папку». В VS Code откройте папку и используйте уже настроенную интеграцию OpenCode из темы 3.4.

cd путь/к/Проект_оценщик opencode

Попросите сначала показать план

Вставьте запрос ниже. Проверьте, что помощник перечислил три заявки и критерии. Если в плане есть неожиданные действия, уточните его до подтверждения.

Прочитай AGENTS.md, task.md, rubric.md и три файла из папки проекты. Пока ничего не меняй и не создавай. Сначала покажи план: перечисли источники, поля которые будешь сравнивать, как обработаешь отсутствующие сведения и какие два файла создашь после подтверждения. Каждую оценку нужно будет подтверждать короткой точной цитатой и названием файла. Не принимай решение о финансировании.

Подтвердите выполнение

После проверки плана отправьте агенту:

Выполняй план. Создай только результаты/отзыв_авторам.md и результаты/сводка_ведущему.md. Для каждого критерия укажи оценку 0–4 либо «нет данных», краткое основание и точную цитату с именем исходного файла. Не меняй исходники, rubric.md, AGENTS.md или task.md. Не добавляй рейтинг и не рекомендуй принять или отклонить проекты.

Откройте отчёты рядом с исходниками

Проверьте суммы, сроки и цитаты вручную. В архиве есть образец сводки для сравнения после запуска, запрос для проверки спорной формулировки и вариант новой рубрики.

Что должно быть установлено

В курсе используется OpenCode 1, установленный в теме 3.4. Если он уже работает, для этой практики ничего дополнительно ставить не нужно. Требуются компьютер, интернет для обращения к настроенной модели и OpenCode CLI, Desktop или настроенная интеграция для VS Code.

Если повторяете с нуля на macOS

  1. Установите Node.js LTS с официальной страницы, если используете установку OpenCode через npm.
  2. Установите OpenCode 1 по официальной инструкции командой из курса либо используйте приложение Desktop.
  3. Откройте Terminal и проверьте:
node --version npm --version npm install -g opencode-ai@1 opencode --version

Если версии показаны, базовая установка доступна. Подключите провайдера через /connect в CLI или в настройках Desktop. Уточните условия доступа у провайдера.

Если повторяете с нуля на Windows

  1. Установите Node.js LTS с официальной страницы, если используете OpenCode через npm.
  2. Установите OpenCode 1 для Windows по официальной инструкции; можно использовать Desktop.
  3. В PowerShell проверьте:
node --version npm.cmd --version npm.cmd install -g opencode-ai@1 opencode --version

Для Windows инструкции OpenCode также описывают вариант WSL. Инструкция 3.4 курса содержит принятый здесь маршрут установки.

Для оценщика проектов дополнительный код не нужен. Не устанавливайте Python, парсеры, MCP-сервер или плагины специально для «Оценщика проектов». Для сценария локального анализа ниже потребуется Python 3. Если команда opencode не найдена или модель не подключена, сначала повторите настройку OpenCode из темы 3.4.
Как настроить подключение модели

Для CLI запустите opencode и введите /connect. В Desktop или расширении откройте настройку провайдера в интерфейсе. Не вставляйте ключи доступа в учебные файлы и не публикуйте их на странице курса. Названия пунктов могут отличаться между CLI и Desktop.

Новая рубрика

Добавьте критерий

Скопируйте rubric.md как rubric-v2.md, добавьте проверку доступности материалов и пересчитайте три заявки по шести критериям. Для этой версии отсутствие сведений обозначайте «нет данных», не включайте его в сумму.

Следуйте рубрике: v1 задаёт 0, если полная заявка не раскрывает критерий; в v2 для доступности отсутствие сведений обозначается «нет данных» и не включается в сумму.

Запрос на сравнение редакций

Сравни проекты/проект_мастерская.md и проекты/проект_мастерская_v2.md. Создай только результаты/сравнение_версий.md с разделами «Исправлено», «Осталось уточнить», «Новое расхождение». Для каждого вывода приведи короткую цитату и укажи файл/версию. Проверь сумму расходов во второй версии отдельно; покажи сложение. Не меняй проекты и не выноси решение о финансировании.

Полный запрос для новой рубрики и контрольные ответы находятся в архиве проекта.

Сценарий 2

Агент анализирует отчёты и документы

Три ежемесячных отчёта учебной мастерской нужно превратить в понятную сводку для преподавателя. В этом примере агент читает тексты документов и сам сопоставляет факты, планы и результаты.

Скачать учебные отчёты и запросы

Что получим

Сводный отчёт с показателями, ссылками на исходники и противоречиями; отдельный список вопросов для уточнения.

Что проверим

Было ли выполнено запланированное число занятий, сходятся ли итоги и можно ли по посещениям судить о количестве студентов.

Шаг 1. Попросите агента изучить отчёты

Распакуйте архив, откройте папку Агент_отчётов в новой сессии OpenCode и отправьте запрос:

Прочитай только три файла из папки отчёты: сентябрь.md, октябрь.md и ноябрь.md. Ничего пока не создавай и не меняй. Покажи таблицу: месяц, число проведённых занятий, число посещений, проблемы и выполненные действия. Для каждого факта укажи файл и короткую точную цитату. Отдельно перечисли недостающие сведения, расхождения между планом и фактом и внутренние противоречия. Не называй посещения числом уникальных студентов, не выдумывай причины и не делай выводов об эффективности без данных. Предложи план сводного отчёта.

Шаг 2. Подготовьте документы

Используя только три прочитанных отчёта и проверенную таблицу, создай два файла: результаты/сводный_отчёт.md и результаты/вопросы_для_уточнения.md. В сводке покажи показатели по месяцам, сложение занятий и посещений, выполненные действия, существенные пробелы и расхождения, со ссылками на имена исходных файлов и короткими цитатами. Покажи оба значения, если они противоречат друг другу, и не исправляй документы за автора. В вопросах попроси уточнить спорные или отсутствующие данные, не выдумывая ответы. Исходники не изменяй. Не принимай управленческих решений.

Шаг 3. Проверьте по исходникам

  • Занятия: 4 + 5 + 5 = 14, хотя в ноябрьской сводной строке указано 15. Причина расхождения неизвестна.
  • Посещения: 48 + 55 + 45 = 148 посещений. Это не количество уникальных студентов.
  • На ноябрь планировали 6 занятий, провели 5; причина не указана. Микрофон заменили.
  • За ноябрь нет сведений об опозданиях: отсутствие данных не означает, что опозданий не было.
В этом сценарии модель читает документы. Для реальных отчётов заранее проверьте, разрешено ли передавать их выбранному сервису. Ниже показан другой подход для таблиц, данные которых модели передавать нельзя.
Сценарий 3

Анализ таблицы без передачи реальных данных модели

Модель пишет скрипт на синтетическом примере. После проверки скрипт обрабатывает реальную таблицу отдельно на компьютере преподавателя.

Скачать таблицу и скрипт

Что в архиве

Вымышленная таблица пример.csv, запрос для создания скрипта и готовый учебный анализ.py. Для запуска нужен Python 3; дополнительные библиотеки не требуются.

Что считаем

Для каждой группы: число записей и пропусков, сумму выполненных и заданных работ и общий процент. Пропущенный результат не считается нулём и исключается из расчёта.

Попробуйте на учебной таблице

  1. Распакуйте архив и откройте запрос ЗАДАНИЕ_МОДЕЛИ.md. Дайте модели только учебный пример и описание задачи.
  2. Прочитайте полученный код: какие файлы он открывает, есть ли сетевые обращения, внешние зависимости или запуск других программ. Готовый скрипт в архиве — подготовленный пример, не ответ текущего запуска.
  3. Запустите проверенный скрипт в обычном терминале из папки с файлами:
python3 анализ.py пример.csv сводка_пример.csv

В Windows вместо python3 можно использовать py -3. Откройте полученный файл локально. Ожидаемый результат: группа А — 14 из 20, 70,0%, один пропуск; группа Б — 26 из 30, 86,7%.

Как перейти к реальным данным

Реальный файл не открывайте в агенте. Проверьте правила организации, подготовьте локальную CSV-копию нужных столбцов и храните её вне папки агента и облачной синхронизации. Закройте сессию агента, отключите сеть и запустите самостоятельно проверенный скрипт в обычном терминале. Не передавайте модели реальные строки, сводку или сообщения об ошибках. Если формат отличается, меняйте код на новом синтетическом примере.

Скрипт читает CSV в UTF-8 с разделителем «;» и заголовками группа;выполнено;задано. Исходник не изменяется, существующий результат не перезаписывается; неверные данные останавливают расчёт. Сводка также может содержать чувствительную информацию, особенно для малых групп.

Проверьте результат перед использованием

  • В каждом выводе есть цитата из исходника
  • Баллы не расходятся с рубрикой
  • Ноль и «нет данных» применены по правилу рубрики
  • Суммы и сроки сверены отдельно
  • Исходная заявка осталась без изменений
  • Отзыв автору отделён от внутренней сводки
  • Черновик не выдан за решение комиссии
  • Реальные заявки не загружались без проверки правил
Используйте только учебные файлы. Если меняете их на документы своей организации, заранее удалите личные данные и проверьте правила выбранного сервиса для передачи документов.
