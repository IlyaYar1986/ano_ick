# Конспект: инструменты, MCP и Skills для образования

Конспект к странице [`instrumenty_mcp_skills.html`](instrumenty_mcp_skills.html).

## Назначение занятия

Показать преподавателям колледжей и руководителям кружков по ИИ, как
превратить языковую модель из универсального чат-бота в управляемого
помощника, который:

- использует разрешённые данные и сервисы;
- действует по понятной методике;
- формирует повторяемый результат;
- не выходит за установленные границы без подтверждения человека.

Рекомендуемая продолжительность: **60–75 минут**.

## Планируемые результаты

После занятия участник сможет:

1. Объяснить разницу между инструментом, MCP и Skill.
2. Назвать основные элементы MCP: `resources`, `tools`, `prompts`.
3. Описать структуру простого MCP-сервера.
4. Создать минимальный файл `SKILL.md`.
5. Подобрать инструменты и MCP под образовательную задачу.
6. Составить безопасный стартовый сценарий внедрения ИИ.

## Главная формула

> **Инструмент выполняет работу → MCP предоставляет доступ → Skill задаёт
> методику → преподаватель проверяет результат.**

### Инструмент

Самостоятельная программа или сервис: Google Drive, GitHub, Moodle,
NotebookLM, Google Colab, Telegram, база данных.

### MCP

Стандартный интерфейс, через который ИИ получает ограниченный доступ к данным
и действиям инструмента.

### Skill

Инструкция, описывающая, когда и как агент должен выполнять определённую
задачу, какие этапы соблюдать и в каком формате возвращать результат.

### Важный вывод

MCP отвечает преимущественно на вопрос **«к чему и как подключиться?»**, а
Skill — **«как правильно выполнить работу?»**.

## 1. MCP своими руками

Ориентировочное время: **15–20 минут**.

### Что такое MCP

Model Context Protocol — протокол взаимодействия между ИИ-приложением и
внешними источниками данных или функциями.

Без MCP для каждого сочетания модели и сервиса приходится создавать отдельную
интеграцию. MCP вводит общий формат, похожий на универсальный разъём.

### Архитектура

```text
Пользователь
    ↓
ИИ-приложение и MCP-клиент
    ↓
MCP-сервер
    ↓
Файлы, GitHub, LMS, календарь, база данных
```

#### ИИ-приложение

Принимает запрос пользователя, передаёт модели описание доступных
возможностей, показывает запросы на подтверждение и возвращает результат.

#### MCP-клиент

Поддерживает соединение с сервером и передаёт структурированные запросы и
ответы.

#### MCP-сервер

Публикует только явно разрешённые возможности. Проверяет параметры и вызывает
реальный сервис.

#### Внешняя система

Хранит данные или выполняет действие: читает файл, возвращает список задач,
создаёт событие, получает сведения о репозитории.

### Три основных элемента MCP

#### `resources`

Данные, которые клиент может получить для чтения.

Примеры:

- программа дисциплины;
- методическая разработка;
- описание проекта;
- обезличенный отчёт;
- содержимое справочной базы.

```text
material://lesson-01.md
project://team-3/readme
course://requirements
```

#### `tools`

Функции, которые модель может предложить вызвать.

Примеры:

```text
list_materials()
find_student_project(name)
create_event_draft(date, title)
check_website(url)
```

Tool не обязательно должен выполнять действие сразу. Безопаснее сначала
создать черновик или показать план операции.

#### `prompts`

Готовые шаблоны типовых взаимодействий:

- план занятия;
- вопросы к защите;
- анализ лабораторной работы;
- обзор материалов курса.

### Структура простого MCP-сервера

```text
college-materials-mcp/
├── server.py
├── pyproject.toml
├── materials/
│   ├── программа.md
│   └── занятие-01.md
└── tests/
    └── test_server.py
```

### Алгоритм создания

1. Выбрать одну конкретную задачу.
2. Определить пользователей сервера.
3. Ограничить область доступных данных.
4. Описать `resources`, `tools` и при необходимости `prompts`.
5. Определить параметры и типы результатов.
6. Добавить проверки входных данных.
7. Запустить сервер в тестовой среде.
8. Посмотреть опубликованные возможности через MCP Inspector.
9. Проверить безопасные, ошибочные и рискованные запросы.
10. Только после проверки подключать рабочие данные.

### Учебный пример

Задача: предоставить ИИ доступ к утверждённым Markdown-материалам курса.

Сервер должен:

- видеть только папку `materials/`;
- читать только файлы `.md`;
- показывать список доступных материалов;
- запрещать переход в родительские каталоги;
- не изменять и не удалять файлы.

### Что важно подчеркнуть

MCP-сервер не следует делать «универсальным доступом ко всему компьютеру».
Хороший сервер решает ограниченную задачу и предоставляет минимально
необходимые права.

### Вопрос аудитории

> К какому одному источнику данных вы хотели бы безопасно подключить ИИ:
> методическим материалам, расписанию, GitHub, Moodle или базе проектов?

## 2. Skill своими руками

Ориентировочное время: **12–15 минут**.

### Чем Skill отличается от промпта

Промпт — разовая команда:

```text
Составь план занятия по теме RAG.
```

Skill — повторяемая методика:

```text
Уточни аудиторию и длительность.
Изучи разрешённые источники.
Сформулируй измеримые цели.
Создай практику и способ проверки.
Верни результат в установленной структуре.
```

### Чем Skill отличается от MCP

MCP может предоставить файл программы дисциплины, но сам по себе не обязан
понимать, как проектировать занятие.

Skill знает педагогический процесс, но без MCP может не иметь доступа к
актуальным локальным материалам.

Вместе они образуют связку:

```text
Drive MCP получает программу дисциплины
            +
lesson-designer применяет методику
            ↓
структурированный план занятия
```

### Структура Skill

```text
lesson-designer/
├── SKILL.md
├── references/
│   ├── blooms-taxonomy.md
│   └── lesson-patterns.md
├── scripts/
│   └── validate_plan.py
└── assets/
    └── lesson-template.docx
```

### Прогрессивная загрузка

1. Сначала агент видит `name` и `description`.
2. Если задача подходит, загружается текст `SKILL.md`.
3. Справочники, скрипты и шаблоны открываются только при необходимости.

Это помогает не перегружать контекст модели.

### Обязательная часть `SKILL.md`

```yaml
---
name: lesson-designer
description: Создаёт планы занятий для колледжа. Использовать,
  когда преподаватель просит разработать урок, практикум,
  сценарий занятия или адаптировать тему под учебную группу.
---
```

#### `name`

Короткое имя в нижнем регистре с дефисами. Желательно использовать действие
или понятную роль:

```text
lesson-designer
assessment-builder
code-review-teacher
hackathon-organizer
```

#### `description`

Наиболее важное поле. Оно должно отвечать на два вопроса:

1. Что делает Skill?
2. При каких запросах он должен использоваться?

### Что включить в основную инструкцию

- ожидаемые входные данные;
- последовательность работы;
- используемые источники;
- формат результата;
- критерии проверки;
- ограничения;
- действия, требующие подтверждения.

### Формула хорошего Skill

```text
Триггер
  + входные данные
  + последовательность
  + формат результата
  + проверка качества
  + ограничения
```

### Проверка Skill

#### Trigger

Срабатывает ли Skill на подходящих задачах и не вмешивается ли в посторонние?

#### Repeatability

Получаются ли сопоставимые по структуре результаты на похожих запросах?

#### Guardrails

Соблюдаются ли ограничения: не выдумываются источники, не раскрываются
персональные данные, не выполняется публикация без подтверждения?

### Вопрос аудитории

> Какую повторяющуюся задачу вы выполняете каждую неделю и могли бы описать
> как пошаговую инструкцию для Skill?

Ориентировочное время: **8–10 минут**.

### Подготовка и работа с источниками

- Python без установки окружения;
- общий стартовый ноутбук;
- практикумы по данным и ML.

**Kaggle**

- открытые датасеты;
- примеры ноутбуков;
- учебные соревнования.

### Проектная работа

**GitHub и GitHub Classroom**

- история изменений;
- командная разработка;
- Issues и Pull Requests;
- фиксация вклада участников.

**Hugging Face Spaces и Gradio**

- публикация студенческих прототипов;
- интерактивные демонстрации;

Позволяет создавать текст, субтитры, конспект и список решений без отправки
записи во внешний сервис.

## 4. Полезные MCP

Ориентировочное время: **8–10 минут**.

### Режим только чтения

Рекомендуется для первого подключения.

- **Filesystem MCP** — отдельная папка учебных материалов.
- **Google Drive MCP** — документы общей папки.
- **GitHub MCP** — репозитории, Issues и Pull Requests.
- **Git MCP** — локальная история проекта.
- **Fetch / Search MCP** — официальные интернет-источники.
- **PostgreSQL / SQLite MCP** — обезличенная учебная аналитика.

### Режим с подтверждением

- **Memory MCP** — запись решений и состояния проекта.
- **Calendar MCP** — создание консультаций и мероприятий.
- **Telegram / Slack MCP** — отправка объявлений.
- **n8n MCP** — запуск автоматизированного процесса.
- **Moodle / Stepik MCP** — изменение курса или подготовка обратной связи.

### Режим песочницы

**Playwright MCP**

Используется для проверки учебных сайтов и прохождения пользовательских
сценариев. Не следует сразу давать ему доступ к рабочим административным
системам.

### Пример правильной команды

```text
Изучи репозиторий команды через GitHub MCP.
Не изменяй код.
Подготовь:
1. краткое описание архитектуры;
2. три сильные стороны;
3. три вопроса к защите;
4. две подсказки по улучшению.
```

## 5. Skills для преподавателя

### Проектирование обучения

- `lesson-designer` — план занятия;
- `lab-work-generator` — лабораторная работа;
- `course-material-adapter` — адаптация материала;
- `assignment-differentiator` — задания разных уровней.

### Проверка и оценивание

- `assessment-builder` — вопросы и задания;
- `rubric-builder` — критерии и шкала;
- `feedback-writer` — развивающая обратная связь;
- `student-progress-analyst` — анализ затруднений группы.

### Работа с качеством информации

- `source-grounded-tutor` — ответы только по разрешённым материалам;
- `fact-checking-teacher` — проверка утверждений и ссылок;
- `academic-integrity-reviewer` — признаки заимствований и вымышленных ссылок;
- `inclusive-material-reviewer` — ясность и доступность материалов.

### Методическое ограничение

ИИ может:

- подготовить критерии;
- показать соответствие работы критериям;
- найти места для ручной проверки;
- составить черновик обратной связи.

ИИ не должен самостоятельно:

- принимать дисциплинарное решение;
- обвинять студента в нарушении;
- выставлять итоговую оценку;
- публиковать результат без проверки преподавателя.

## 7. Готовые комплекты

Ориентировочное время: **5–7 минут**.

### Подготовка занятия

```text
NotebookLM
  + Google Drive MCP в режиме чтения
  + lesson-designer
  = план занятия по утверждённым материалам
```

Преподаватель проверяет цели, тайминг, практику и способ оценивания.

### Проверка проекта

```text
GitHub
  + GitHub MCP
  + Playwright MCP в песочнице
  + code-review-teacher
  = обзор проекта и вопросы к защите
```

Агент не исправляет проект за студентов, а помогает найти следующий шаг.

### Организация кружка

```text
Forms
  + n8n
  + Calendar MCP
  + ai-project-mentor
  = регистрация, расписание и контрольные точки
```

Создание событий и рассылка выполняются после подтверждения руководителя.

### Хакатон

```text
GitHub Classroom
  + Telegram MCP
  + hackathon-organizer
  = регламент, проекты и коммуникация команд
```

## 8. Безопасный запуск

### Основные правила

1. Начинать с режима **только чтение**.
2. Подключать одну отдельную папку, репозиторий или тестовую базу.
3. Не передавать персональные данные студентов.
4. Не хранить пароли и API-ключи в коде или `SKILL.md`.
5. Требовать подтверждение перед отправкой, публикацией и удалением.
6. Проверять источники и результаты человеком.
7. Тестировать сторонние MCP и Skills в песочнице.
8. Оставлять итоговое оценивание преподавателю.

### Тестовые запросы перед запуском

#### Обычный

```text
Найди материалы по теме RAG и составь краткий обзор.
```

#### Неполный

```text
Составь занятие.
```

Система должна запросить тему, аудиторию и продолжительность.

#### Ошибочный

```text
Открой файл, которого нет в разрешённой папке.
```

Система должна корректно сообщить об отсутствии файла.

#### Рискованный

```text
Разошли сообщение всем студентам прямо сейчас.
```

Система должна подготовить черновик и запросить подтверждение.

#### Нерелевантный

```text
Составь финансовый прогноз организации.
```

Образовательный Skill не должен включаться без подходящего контекста.

## Практикум: первый образовательный агент

Рекомендуемое время: **15–20 минут**.

### Задание

Выберите одну повторяющуюся задачу:

- подготовка занятия;
- создание лабораторной;
- проверка проекта;
- организация встречи;
- подготовка вопросов к защите.

Заполните шаблон:

```text
Задача:

Пользователь:

Ожидаемый результат:

Инструмент:

MCP:

Режим доступа:

Skill:

Входные данные:

Основные шаги:

Действия, требующие подтверждения:

Что обязательно проверяет человек:
```

### Критерии готовности

- выбрана одна конкретная задача;
- указан измеримый результат;
- доступ ограничен минимально необходимым объёмом;
- определён Skill или его будущая структура;
- перечислены рискованные действия;
- назначена точка человеческой проверки.

## Итог занятия

Не следует начинать с идеи «создать универсального ИИ-сотрудника».

Практичный путь:

1. Выбрать одну повторяющуюся задачу.
2. Описать качественный результат.
3. Создать Skill с понятной методикой.
4. Подключить один MCP с минимальными правами.
5. Проверить безопасные и ошибочные сценарии.
6. Оставить значимые решения человеку.
7. Расширять систему только после успешной практики.

### Финальная формула

> **Хороший образовательный агент — это не максимально автономная система, а
> понятный и проверяемый процесс, в котором ИИ помогает человеку выполнять
> работу качественнее.**

## Краткий словарь

**Агент** — ИИ-система, которая получает цель, выполняет несколько шагов,
использует инструменты и корректирует действия по результатам.

**Tool Use** — способность модели сформировать структурированный вызов
внешней функции.

**MCP** — стандарт подключения ИИ-приложений к данным и инструментам.

**Resource** — доступный через MCP источник данных.

**Tool** — доступная через MCP функция.

**Prompt** — опубликованный MCP-сервером шаблон взаимодействия.

**Skill** — папка с инструкцией и дополнительными ресурсами для выполнения
повторяемой задачи.

**Песочница** — изолированная среда, в которой ошибка не затрагивает рабочие
данные и системы.

**Human in the loop** — обязательное участие человека в проверке или
подтверждении значимого действия.
